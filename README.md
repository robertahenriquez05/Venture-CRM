# Venture-CRM
Venture-CRM is a lightweight web app for tracking early-stage founder relationships; advisors, mentors, and investor contacts, along with where each relationship stands and what follow-up is needed next. Built for solo founders who don't need a full-scale CRM, just a simple way to keep track of who they've talked to and what's pending. Built with Python and Django.

## Logging and runbooks

The app writes structured JSON logs (one object per line) to the terminal and to `logs/venture-crm.jsonl`. Every request gets a `request_id` that appears on all of its log lines, in the `X-Request-ID` response header, and as the "Reference code" on the error page.

- Read the log: `python scripts/logq.py --failed`, `python scripts/logq.py <request_id>`, `python scripts/logq.py --last 20`
- Field reference and a traced example: [`docs/m8/README.md`](docs/m8/README.md)
- Runbooks: [`RB-001: "Add contact" shows an error page`](docs/runbooks/RB-001-add-contact-error-page.md)

## Running it live (Render)

**Live:** https://venture-crm.onrender.com (placeholder demo data only)

**Signing in:** username `demo`. The password is generated by Render: dashboard -> venture-crm -> Environment -> `VENTURE_CRM_DEMO_PASSWORD`. The same account opens `/admin/`. `build.sh` runs `ensure_demo_user` on every deploy, so changing that variable and redeploying changes the password.

The app is deployed on Render's free tier from `render.yaml` (a Blueprint): one web service running `gunicorn`, and one free Postgres database.

- `build.sh` runs on every deploy: install, `collectstatic`, `migrate`, then `seed_demo` (loads 8 placeholder contacts only if the database is empty).
- Production settings come from environment variables: `DJANGO_DEBUG=False`, `DJANGO_SECRET_KEY` (generated by Render), `DATABASE_URL` (from the Render database). `RENDER_EXTERNAL_HOSTNAME` is added to `ALLOWED_HOSTS` automatically.
- Locally nothing changes: no env vars means SQLite, DEBUG on, the dev secret key.
- Free-tier limits: the service sleeps after ~15 minutes idle (first request takes ~1 minute to wake), and the free Postgres database expires 30 days after creation.
- Demo data: `python manage.py seed_demo` (add `--reset` to wipe and reload). All demo contacts are fake, with `@example.com` emails.


## Features

- **Contacts** (`/`): add, search (name, company, email), filter by tag, per-stage counts, follow-ups panel (overdue / today / upcoming).
- **Contact page** (`/contacts/<id>/`): edit details, stage, follow-up date and tags; interaction log (call / email / meeting); stage history with time in the current stage; delete (with a confirmation page).
- **Pipeline** (`/pipeline/`): one column per stage; drag a card to move it (works without JavaScript too, via the dropdown on each card).
- **Sign-in required** on every page (`LoginRequiredMiddleware`); `/healthz` is the only open URL.
- Decisions: [ADR-001](docs/adr/ADR-001-pipeline-stage-as-choices-field.md) (stage as a choices field), [ADR-002](docs/adr/ADR-002-record-stage-history.md) (append-only stage history).

Local sign-in: `python manage.py createsuperuser`.
